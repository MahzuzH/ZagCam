# M4 performance report

Generated by `tools/bench.ps1` on the reference laptop (720p, release build). The idle sample
closes the settings window first, so it measures the tray process with no consumer. Latency is
decode plus effect per probe frame; it excludes the camera frame wait. `latest.md` is the current
run; `opt-s-run*.md` and `opt3-run*.md` are the reproducibility evidence.

## Budgets

| Budget | Target | Measured | Status |
| --- | ---: | ---: | --- |
| Installer/package | ≤ 30 MiB | 11.37 MiB compressed | pass |
| Active CPU, eco | ≤ 32% of one core | 16.8–26.1% | pass |
| Active RAM, eco | ≤ 100 MiB | 49.2 MiB | pass |
| Idle RAM | ≤ 15 MiB | 73.4 MiB | **exception** |
| Idle CPU | ~0% | 0–0.5% | pass |
| Time to first frame | ≤ 1.5 s | 224–248 ms | pass |
| Capture-to-output latency | ≤ 100 ms | p95 ≤ 50.3 ms | pass |
| Frame rate | 30 fps, never below 24 | 19.3 fps | **exception** |

## Exceptions

- **Frame rate (owner: ZagCam maintainer).** The source camera on the reference laptop delivers
  ~19 fps at 1280x720 and 640x360, in NV12, MJPEG, and YUYV (raw frame loop, no processing). The
  pipeline keeps up: off mode is also 19.3 fps, and the per-frame effect work fits the 30 fps
  budget. The 24 fps floor cannot be validated until Sprint 12 runs a camera that actually
  delivers 30 fps. Engine-side sleep that capped the consumer path near 20 fps was removed.
- **Idle RAM (owner: ZagCam maintainer).** `eframe`/`glow` keeps ~73 MiB even after the settings
  window is closed; closing it saves under 1 MiB. M5 desktop-shell work will lazy-create the
  settings window or move it to a native Win32 window. Until then, keep the exception rather than
  claiming the 15 MiB target.

## Profile and build tradeoffs

Balanced mode per-frame rank (opt-level 3, median): decode ~5.8 ms, composite ~3.7 ms,
inference ~3.5 ms amortized (every 2nd frame), blur ~2.7 ms, preprocess ~1.3 ms, mask ~1.1 ms.

| Release setting | ZagCam.exe | Package | Balanced CPU | Balanced p50 latency |
| --- | ---: | ---: | ---: | ---: |
| `opt-level = "s"` | 33.14 MiB | 10.74 MiB | 81.9–85.6% | 26.9–27.1 ms |
| `opt-level = 3` | 34.14 MiB | 11.37 MiB | 53.0–56.7% | 20.0–20.5 ms |

`opt-level = 3` costs ~1 MiB and stays far below the package budget, so the release profile uses it.

## DirectML

`ort-sys` only ships a DirectML-enabled Windows prebuilt, even for the CPU execution provider. The
app never registers DirectML, and inference works with `DirectML.dll` removed. `copy-dylibs` is
disabled for `ort`, so the DLL is no longer copied into `target/release` or the package.
